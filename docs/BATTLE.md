# Механика боя при энкаунтерах — спецификация

> Рабочий код: `handlers/battle.py` · данные: `data/adventure/{locations,mobs,global_pool}.json` · тексты: `texts/battle.yaml` · тесты: `tests/test_battle.py`.
> Документ описывает логику в том виде, в котором она реализована (коммит `6baed76`).

## 1. Общая схема

```
/start или /adventure
  └─ выбор локации (adv_loc_)
      └─ «Отправиться» (adv_expedition_)
          ├─ создаётся active_expedition (start/end/encounter_scheduled/encounter_at)
          ├─ джоба expedition_{uid}   — завершение экспедиции
          └─ джоба encounter_{uid}    — момент энкаунтера (если выпал по шансу)
              └─ срабатывает случайное время внутри экспедиции
                  └─ try_start_battle() -> active_battle
                      └─ сообщение боя с кнопками (фазы, раунды)
                          ├─ ПОБЕДА: награды здесь и сейчас; экспедиция продолжается
                          │   └─ запись в battle_log -> попадает в итоговый отчёт
                          └─ ПОРАЖЕНИЕ: экспедиция прерывается здесь и сейчас
                              └─ 1 HP, без опыта, минимальный лут
```

Завершение экспедиции (`expedition_{uid}`, страховочная джоба раз в 60 с, клик игрока)
**не трогает экспедицию, пока идёт бой** — откладывается и повторяется после боя.

## 2. Планирование энкаунтера

- При старте экспедиции бросается `encounter_chance` **локации** (`plan_encounter`).
- Если выпал — момент выбирается случайно в окне **[30 с … конец − 60 с]** таймера экспедиции.
- В запись экспедиции пишутся `encounter_scheduled: true` и `encounter_at` (ISO).
- Джоба `encounter_{uid}` — быстрый триггер; сторож (см. §10) подхватит пропущенное.

## 3. Выбор врага (`build_battle_enemy`)

Первый сработавший источник:

1. **Босс локации** — бросок `encounter_chance` по списку `bosses` локации (первый успех).
2. **Специфичные мобы локации** — реестр `mobs.json → specific_mobs[loc_id]`,
   взвешенный выбор по их `encounter_chance`; имя/описание резолвятся из
   текстовых ключей `adventure.{mob_id}_name/_desc`, иначе — инлайн-поля.
3. **Сгенерированный моб** — редкость по `encounter_weights` (common/uncommon/rare/boss),
   имя из `mob_types[rarity].names[loc_id]`.

## 4. Раунд: фазы и зоны

Zones: `head` / `body` / `dick` (кнопки и тексты в `battle.yaml`).

Каждый раунд:

1. Враг **скрытно** выбирает независимо `enemy_attack` и `enemy_block` (`random.choice`).
2. **Фаза атаки (10 с)** — игрок жмёт зону `advb_{bid}_atk_{zone}`. Выбрал точно /
   не в фазе / устаревший бой → ответ колбэка «не принимается».
3. **Фаза защиты (10 с)** — кнопки `advb_{bid}_blk_{zone}`; выбор блока решает раунд сразу.
4. Таймаут любой фазы → отсутствующий выбор заполняется случайной зоной
   (помечается ⌛ в журнале) → бой всегда завершается даже без игрока.

## 5. Расчёт раунда (`_resolve_round`, чистая функция без Telegram API)

```
hit     = player_attack != enemy_block      # 2/3 при равномерном скрытом выборе
blocked = player_block  == enemy_attack    # 1/3 игомень закрыл гнома иным блоком
```

- Порядок: **сначала атака игрока**. Победное попадание гасит ответный удар того же раунда — ничьи в пользу игрока.
- Неблокированная атака врага: `dmg_taken += dmg_per_hit`.
- Поражение: `hp − dmg_taken ≤ 0` (HP гнома не уходит ниже 1 — с UI «еле дополз»).
- Победа: `hits ≥ win_hits` (лимита числа раундов нет; журнал ограничен 20 записями).

## 6. Исходы

### Победа (применяется атомарно под `_EXPEDITION_LOCK`)

| Награда | Значение |
|---|---|
| XP | common 10 · uncommon 15 · rare 25 · босс `10 + base_reward` |
| Лечение | +20 HP (сверх восстановленного после урона) |
| Предмет | мобы: шанс **50%** + случайный id из `mobs.json → loot_table[tier].items` → имя из `global_pool.json → items`; боссы: свой `loot`-таблица по шансам |
| Статистика | `wins`, `total_fights` +1; XP уходит в порог уровня (`50 + N×50`, +20 max HP) |

Итог боя пишется в `active_expedition.battle_log` (враг, раунды, XP, предмет) —
и попадает в финальный отчёт экспедиции.

### Поражение

- HP = 1, XP = 0, боёв +1.
- Минимальный лут: **один** ресурс локации с шансом 25%.
- Экспедиция завершается немедленно: отчёт боя отправляется, `active_expedition` очищается.

### Формат отчётов («дуэльный» стиль)

- Художественные описания раундов — из каталогов фраз в `texts/battle.yaml`
  (`final_blow_phrases`, `attack_hit_phrases`, `attack_miss_phrases`,
  `counter_blocked_phrases`, `counter_hit_phrases`); выбор — `random.choice`
  в коде, тексты живут только в YAML (см. TEXT_MIGRATION_AUDIT: порядок RNG-вызовов не менять).
- Арт решающего раунда стоит вверху отчёта; далее блок «🗡 Итоги боя» (враг, попадания,
  урон, длительность), награды, «📓 Хроника боя» и случайная гномья байка (`lore_quotes`) в конце.
- Арт последнего раунда также приходит в фазовых сообщениях («⚔️ {username} против {enemy}»)
  — мгновенная реакция на только что отыгранный раунд.
- Журнал раунда хранит скрытые зоны врага (`enemy_attack`/`enemy_block`) —
  они нужны для описания ответок.

## 7. Параметры врагов

Дефолты по тирам (`mobs.json → battle_defaults`), переопределяются per-моб/per-босс ключом `battle`:

| Тир | win_hits | dmg_per_hit | Кто|
|---|---|---|---|
| common | 1 | 25 | куст (25), голова деда (30) |
| uncommon | 2 | 40 | смоляной слуга (35) |
| rare | 2 | 55 | сгенерированные rare |
| boss | 3 | 60 | барон (50), тролль (60), шаман* (2/50), дракон (60), дракончик* (2/45) |

\* шаман и дракончик — outlier'ы в меньшую сторону по `battle`-ключу.

## 8. Баланс (Монте-Карло по реальному коду правил, 50 000 симуляций/ячейка)

Вероятность победы гнома (обе стороны — авто-рандом):

| Враг | 200 HP | 120 HP | 80 HP | 40 HP |
|---|---|---|---|---|
| common (1/25) | 100% | 99.9% | 99.7% | 94% |
| uncommon (2/40) | 98.9% | 88% | 66% | 19% |
| rare (2/55) | 96.3% | 88% | 66% | 19% |
| босс 3/50 | 83.4% | 61.7% | 27.2% | 4.7% |
| босс 3/60 | 83.4% | 27.2% | 27.2% | 4.7% |

Средняя длина авто-боя — 3 раунда (~1 мин при 2×10 с; активный игрок — 20–30 с).
Хранение HP между экспедициями делает раненых гномов честно уязвимыми.

## 9. Состояние боя

```json
"active_battle": {
  "battle_id": "a1b2c3",
  "location_id": "dark_forest",
  "chat_id": 42, "username": "tester",          // владелец и место боя
  "enemy": {"id", "name", "desc", "tier", "win_hits", "dmg_per_hit",
            "base_reward", "loot", "pool_items"},
  "round": 3, "phase": "attack" | "defense",
  "enemy_attack": "head", "enemy_block": "body",   // скрыты от игрока
  "player_attack": null, "player_block": null,
  "auto_attack": false, "auto_block": false,
  "phase_deadline": "ISO-срок текущей фазы",
  "hits": 1, "dmg_taken": 40,
  "journal": [{"round", "attack", "block", "enemy_attack", "enemy_block",
               "auto", "hit", "blocked", "dmg"}],
  "message_id": 123456                          // какое сообщение правим
}
```

Колбэки: `advb_{battle_id}_{atk|blk}_{zone}` — `battle_id` отсекает кнопки прошлых боёв;
нажимать может только владелец (бой ищется в записи самого нажимающего).

## 10. Устойчивость (переживание рестартов)

- Фазовые таймеры — в памяти; `phase_deadline` лежит в состоянии.
- **`battle_watcher_job`** (каждые 10 с): фаза с истёкшим дедлайном — автопродвижение;
  экспедиция с пропущенным `encounter_at` (и без боя/журнала) — старт боя.
- `advance_battle` проверяет дедлайн под локом, поэтому таймер и сторож
  не конфликтуют (идемпотентно); смена фаз в любом случае перепланирует таймер.
- Завершение экспедиции откладывается при активном бое (джоба откладывается на +60 с).

## 11. Интеграция с экспедицией (`handlers/adventure.py`)

| Точка | Что делает |
|---|---|
| старт экспедиции | `plan_encounter` + запись `encounter_at` + джоба триггера |
| просмотр локации | пометка «⚔️ Гном сейчас в бою!» |
| отмена экспедиции | снимает джобы (завершение / энкаунтер / фаза боя) и `abort_battle()` |
| завершение (`send_expedition_result`) | видит `active_battle` → откладывается и ретраится |
| итоговый отчёт | рендерит `battle_log` (родовые формы врагов, XP, предмет) |

## 12. Карта кода

| Функция (`handlers/battle.py`) | Роль |
|---|---|
| `plan_encounter` | бросок шанса локации + момент внутри окна |
| `build_battle_enemy` | босс → специфичный моб → редкость; боевые параметры |
| `try_start_battle` | атомарный старт боя (одна экспедиция — один бой) |
| `record_battle_choice` | кнопки атаки/блока; переход фаз; сразу рассчитывает раунд |
| `advance_battle` | автопродвижение по `phase_deadline` (таймаут/сторож) |
| `_start_round` / `_resolve_round` | чистая логика раунда |
| `_apply_battle_victory` / `_apply_battle_defeat` | награды/последствия |
| `_settle_battle` | очистка боя + запись итога (atomic с наградами) |
| `battle_callback` / `battle_phase_timeout` / `battle_watcher_job` / `trigger_encounter_job` | async-слой: Telegram и JobQueue |
